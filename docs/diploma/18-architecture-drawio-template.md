Ниже приведена компактная и официально оформляемая структура архитектурной схемы проекта RSH. Она подготовлена для быстрого переноса в draw.io и последующей вставки в дипломную работу.

## Что должна показывать схема

Архитектурная схема должна продемонстрировать, как в системе RSH взаимодействуют:

- пользовательский интерфейс;
- административный интерфейс;
- 2D-конструктор;
- серверные маршруты и серверные действия;
- аутентификация и контроль доступа;
- сервисный слой;
- слой репозиториев;
- база данных;
- Redis;
- файловое хранилище;
- платежный сервис Stripe.

Главная задача схемы — показать комиссии, что приложение построено по многослойной архитектуре, а бизнес-логика не смешана с интерфейсом и хранением данных.

## Как расположить блоки в draw.io

Рекомендуемая структура — сверху вниз, по уровням.

### Верхний уровень — акторы

Слева:
- `Пользователь`

Справа:
- `Администратор`

### Второй уровень — интерфейсы

Под пользователем:
- `Пользовательский интерфейс (Next.js / React)`

Под администратором:
- `Административный интерфейс (Next.js / React)`

Рядом с пользовательским интерфейсом:
- `2D-конструктор (Fabric.js)`

### Третий уровень — сервер

По центру:
- `Серверные маршруты и Server Actions`

Ниже него:
- `Аутентификация и RBAC`
- `Сервисный слой`
- `Слой репозиториев`

### Нижний уровень — данные и внешние сервисы

Слева направо:
- `PostgreSQL / Prisma`
- `Upstash Redis`
- `UploadThing`
- `Stripe`

## Как провести связи

### От акторов к интерфейсам

- `Пользователь -> Пользовательский интерфейс`
- `Администратор -> Административный интерфейс`

### От интерфейсов к серверу

- `Пользовательский интерфейс -> Серверные маршруты и Server Actions`
- `Административный интерфейс -> Серверные маршруты и Server Actions`
- `2D-конструктор -> Серверные маршруты и Server Actions`

### Внутри серверной части

- `Серверные маршруты и Server Actions -> Аутентификация и RBAC`
- `Серверные маршруты и Server Actions -> Сервисный слой`
- `Аутентификация и RBAC -> PostgreSQL / Prisma`
- `Сервисный слой -> Слой репозиториев`
- `Слой репозиториев -> PostgreSQL / Prisma`

### От сервисного слоя к интеграциям

- `Сервисный слой -> Upstash Redis`
- `Сервисный слой -> UploadThing`
- `Сервисный слой -> Stripe`

## Как оформить визуально

Чтобы схема выглядела аккуратно и официально:

1. Акторов можно сделать в виде простых прямоугольников или человечков.
2. Интерфейсы выделить светло-голубым цветом.
3. Серверные блоки выделить светло-зелёным цветом.
4. Блоки хранения данных и внешних интеграций выделить светло-жёлтым или светло-серым.
5. Базу данных можно дополнительно обозначить цилиндром.
6. Stripe, UploadThing и Redis можно оставить прямоугольниками с короткими подписями.

## Что говорить на защите по этой схеме

Архитектурная схема проекта RSH демонстрирует многослойную организацию веб-приложения. Пользовательский и административный интерфейсы работают через серверные маршруты и серверные действия, которые передают управление в сервисный слой. Сервисный слой реализует бизнес-логику и взаимодействует с репозиториями, обеспечивающими доступ к данным в PostgreSQL. Дополнительно система интегрирована с Redis для служебного кэширования и ограничений запросов, с UploadThing для загрузки файлов и со Stripe для обработки онлайн-оплаты. Такая архитектура обеспечивает разделение ответственности, удобство сопровождения и готовность проекта к промышленному развертыванию.
